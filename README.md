# 聚会三国杀

让朋友用手机扫码，一起玩三国杀：一台 Windows 电脑双击启动，玩家无需安装手机软件、注册账号或加好友，可以在同一 Wi-Fi，也可以使用各自的网络。玩家在手机上建房、设置和开局，电脑提供服务与规则执行，不占玩家席位。

对局规则、技能、AI 和手机牌桌来自 [无名杀](https://github.com/libnoname/noname)，固定 v1.11.6／commit `2367607e246d21aae168dba15c01151ee0651f30`。本项目主要负责扫码入口、房间管理、电脑运行和手机接入；感谢上游开发者。

**当前版本：v0.7.13，面向熟人聚会的公开测试版本。** 普通玩家请下载 [Windows x64 启动包](https://github.com/liyan1775/party-sanguosha/releases/tag/v0.7.13)，选择 `party-sanguosha-v0.7.13-windows-x64-setup.zip`，无需安装开发工具。当前运行服务、验证结果和待办统一见 [开发交接](docs/handoff.md)；首发条件见 [发布准备](docs/release-readiness.md)。

## 如何组织一桌

Windows x64 启动包内置运行环境、固定联网组件与准备工具。**首次双击会自动从无名杀上游下载约431 MiB游戏资源**，电脑需要能访问 GitHub 和 raw.githubusercontent.com；耗时取决于网络，窗口显示进度。已下载并校验的文件会保留，中断后再次双击可继续补齐。准备完成后资源在本机保存，同 Wi-Fi 游玩不依赖公网。无需另装 Node.js、Git 或 Codex；源码运行方法见下文。

1. 完整解压，双击 **「启动聚会三国杀.cmd」**，等待自动打开电脑服务页。电脑整局保持联网、页面开启并避免休眠。
2. 同 Wi-Fi／电脑热点的朋友扫局域网码；其他网络的朋友等待公网入口就绪后扫公网码。两种入口可以加入同一个房间。
3. 一位玩家填写昵称、创建房间并入座，成为参赛房主。在手机选择模式、将池，人数不足时添加 AI；设置自动保存。
4. 已入座玩家均可展示本房间二维码。其他朋友扫码、填昵称、准备，由玩家房主开局。
5. 选将后每位真人可免费整手刷新起手牌最多3次，再保留手牌开始。选牌、目标或技能材料后，点击「使用／确定」提交；再次点已选牌可取消。
6. 结算后回到原房，重新准备再开一局。聚会结束双击 **「停止聚会三国杀.cmd」**。

重复双击启动会打开同一实例；关闭浏览器标签不会停止后台。停止或重启服务会清空房间，需要重新建房及分享邀请。请完整保留解压文件夹，不要只复制 `.cmd` 文件。

首次下载需要先完成资源准备，下载时间不计入服务的两分钟等待窗口。准备完成后，每次启动的资源校验可能需要几十秒，启动窗口会持续提示等待，服务就绪最多等待两分钟。校验完成后才打开电脑服务页；若失败，请保留 `.runtime/server.log` 和 `server-error.log` 中的错误信息供维护者检查。

微信锁定竖屏时默认把牌桌横过来，横着握手机即可操作，也可切回竖屏。首次触摸尝试开启声音，工具条提供声音开关及音量调节，仅影响自己的手机。

开发版提供「铜雀军帐」和「宣纸墨局」两套经典界面，页面右上角可切换并记忆选择；牌桌顶部保留记录、声音和更多，音量、二维码、方向及托管等操作分组收起。切换风格保留当前席位、准备和对局。

开发版动画默认 **2倍速度**，房主在等待大厅「房主设置 → 动画与节奏」选择 **1–10倍**，开局后房主不可修改；服务器电脑可在服务页的房间详情调整「本房动画速度」，支持对局中同步。思考时间、手气牌期限和准备状态保持，其他房间单独设置；1倍恢复旧节奏。这些修改位于 `D:\Code\party-sanguosha` 开发副本，尚未更新上述公开启动包。

只想在同一 Wi-Fi 游玩时，双击 **「启动局域网聚会三国杀.cmd」**，无需公网组件。两种启动方式共用本目录的一个实例，切换前先停止。默认启动也始终提供局域网码，公网故障不妨碍 LAN 页面、素材和牌桌。

## 支持什么

| 玩法         | 总席位（包含 AI）           |
| ------------ | --------------------------- |
| 身份局       | 5–8                         |
| 三国杀斗地主 | 3                           |
| 2v2          | 4                           |
| 单挑         | 2，每人一名武将、一局定胜负 |

- 两档基础将池：标准包27将、经典进阶96将；另有八档官方活动／公开目录将池，按具体原生版本核对，缺项有说明，见 [官方将池](docs/official-rosters.md)。仅导入将池，不复制赛事 BP 或计分。
- 标准档使用108张牌；进阶及官方档使用标准加军争、去木牛流马的160张牌。每局冻结名单和牌堆，不覆盖原生技能、体力或出牌 AI。
- AI 可补空位，使用完整原生决策；所有玩家可查武将图鉴。房主可开启点将、管理 AI 和局间交接。
- 手机使用原生选将、牌桌、技能选择与动画；支持主动托管、同浏览器刷新恢复、断线提示和回房第二局。
- 电脑控制台管理房间及公开观战，玩家也可看本局公开记录；暗手牌、未公开身份与私人技能选择不应进入公开投影。
- 支持局间转交房主、房主离线60秒后由在线成员显式接任。等待／已结算房间全员连续离线10分钟后回收，进行中的牌局保留。

## 使用边界

房间、席位和最多10000条本局公开记录保存在内存，重启即清空；不是持久化存档或完整动画回放。电脑规则页关闭、刷新丢失实例或不可恢复故障时，会明确显示中断，不重开一局冒充续局。

默认公网入口使用 Cloudflare Quick Tunnel，无需账号、域名或路由器端口配置，但临时服务没有可用性保证，新建时地址变化。已发布地址中断时保留原码并标明状态，恢复后可继续使用。公网尝试 RTC 直连，失败后使用持续推送或 HTTP；不保证所有 NAT／防火墙可穿透或所有网络低延迟。

同 Wi-Fi 优先用 LAN 码。电脑若有多个网卡，在服务页选手机所在网络；Windows 需允许该服务入站，路由器不能开启客户端隔离。默认尝试3000端口，双击启动发现占用时尝试后续端口，不终止其他程序，以实际打开的服务页为准。

座位绑定原浏览器、原入口的会话。从微信换系统浏览器、从 LAN 地址换公网地址会得到另一会话，需先离座或请房主移除旧席位。短断线期间对局可能继续，超过缓冲可能由 AI 行动，恢复后请核对手牌、体力及托管状态。

2026-10-14用户确认已与朋友使用安卓、iPhone和电脑浏览器在局域网实际游玩，能完成熟人同桌体验；具体手机版本及浏览器未细分，不能据此声称所有组合均通过。公网真机、独立Windows首次启动复测仍待完成，见 [试用清单](docs/beta-testing.md)。某较老Edge被报告缺少鲜花／鸡蛋飞行动画，但不影响游玩；确切版本尚未提供。全部技能动态隐私、多房容量和完整恶意客户端校验尚未验证。

## 从源码运行与开发

需要 **Node.js 24.x**。源码不包含忽略的引擎资源；Windows 双击启动器会准备依赖和固定资源，首次需要下载。命令行方式先准备引擎，再启动：

```powershell
npm ci
npm run engine:prepare
npm start
```

`npm start` 构建并以前台方式启动，`Ctrl+C` 停止。开发时可用 `npm run dev` 监视服务端变化；网页源码改变后重新构建。发行包的双击入口运行预构建页面与服务，首次在本机准备固定引擎，不会编译修改过的应用源码；继续开发请安装完整 Node.js 24、运行 `npm ci` 后用 `npm start`。

```powershell
npm run check
$env:E2E_BROWSER_CHANNEL = 'msedge'
npm run test:browser
npm run test:engine-api
```

`check` 包含类型、领域／HTTP 测试、构建和格式检查。纯源码没有引擎时明确跳过完整资源清单这一项，不能据此称可玩；`test:engine-api` 强制要求完整固定资源。真实选将、发牌、自然结算、重连和第二局验证用 `npm run engine:verify:rooms`，参数见 [适配说明](packages/noname-adapter/runtime/README.md)。旧轻量界面只保留显式研究／回归入口。

在 Windows x64／Node24 环境用 `npm run package:windows -- --starter` 生成公开启动包 ZIP 和 SHA-256；不带 `--starter` 可生成本机完整资源测试包。发布前在本项目 Git 检出运行 `npm run release:check`，再按发布准备文档验收。包和检查报告位于忽略的 `.runtime`，不包含个人 `.env`、当前会话或日志。公开启动包不内置上游图片、音频、字体及其衍生产物，由用户首次启动时从固定上游获取；完整资源包的再分发依据仍单独核对。

可选配置见 [.env.example](.env.example)。开发接续、反馈和验证要求见 [参与开发](CONTRIBUTING.md)。安全问题见 [安全反馈](SECURITY.md)，不要公开 cookie、停止凭据、私人牌面或未经检查的协议日志。
